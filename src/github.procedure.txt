Switching to the new repo

You don’t have to delete anything locally. A local project isn’t tied to a GitHub repo. It’s only linked through its remote URL, so “switching” means pointing the remote at the new repo.

1. See what’s linked now
bash
git remote -v

This shows the old repo’s URL (or URLs).

2. Remove the old remote(s)

Remove whatever names you see listed:

bash
git remote remove origin
git remote remove staging
git remote remove production

Ignore any “No such remote” messages.

3. Add the new repo

Create the new repo on GitHub first (empty: no README, no .gitignore, no license), then:

bash
git remote add origin https://github.com/YOUR_USERNAME/NEW_REPO.git
git remote -v

The URL should have no username or token inside it.

4. Clear the old login

You were logged in for the deleted repo, and that saved credential may belong to the wrong account:

bash
printf "protocol=https\nhost=github.com\n\n" | git credential-osxkeychain erase
5. Create the branches and push

If you haven’t yet:

bash
git branch -M staging
git branch production
git push -u origin staging
git push -u origin production

When prompted, enter the username of the account that owns the new repo, and a token created under that same account.

6. Check it worked
bash
git remote -v
git branch -vv

git branch -vv should show both branches tracking origin/staging and origin/production.


2. The 403 is the same account mismatch as before

“Permission to RehaanQnopy/Attendance-kiosk.git denied to Rehaan4u.”

The repo belongs to RehaanQnopy, but Git is still sending the credential for Rehaan4u. It didn’t prompt you at all, which means a saved login is still being reused. The erase command either wasn’t run or didn’t remove the entry.

Fix it
1. Erase the saved credential
bash
printf "protocol=https\nhost=github.com\n\n" | git credential-osxkeychain erase
2. Confirm it’s gone from Keychain

Open Keychain Access (Cmd+Space), search github.com, and delete every internet password entry you see. The command line erase sometimes misses entries, so check by hand.

3. Check the remote URL
bash
git remote -v

It should be exactly https://github.com/RehaanQnopy/Attendance-kiosk.git, with nothing before github.com. If it contains Rehaan4u@, reset it:

bash
git remote set-url origin https://github.com/RehaanQnopy/Attendance-kiosk.git
4. Push again
bash
git push --set-upstream origin staging

Git should now prompt you:

Prompt	Enter
Username	RehaanQnopy
Password	A token created while logged into RehaanQnopy
5. Then the production branch
bash
git push --set-upstream origin production
